# AI Trading System - Deployment Guide

## Prerequisites

- Docker Desktop or Docker Engine
- Kubernetes cluster (local or cloud)
- Helm 3.x
- Terraform 1.x (for cloud deployment)
- kubectl configured for your cluster

## Local Development Deployment

### 1. Clone Repository
```bash
git clone <repository-url>
cd ai-trading-system
```

### 2. Configure Environment
```bash
cp configs/environments/.env.example .env
# Edit .env with your configuration
```

### 3. Deploy with Docker Compose
```bash
docker-compose up -d
```

### 4. Deploy to Local Kubernetes
```bash
./scripts/deployment/deploy-local.sh
```

## Production Deployment

### 1. Infrastructure Setup
```bash
cd infrastructure/terraform
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars with your configuration
terraform init
terraform plan
terraform apply
```

### 2. Application Deployment
```bash
./scripts/deployment/deploy-production.sh
```

### 3. Verify Deployment
```bash
./scripts/maintenance/health-check.sh
```

## Configuration

### Environment Variables
- `ENVIRONMENT`: deployment environment (development/staging/production)
- `DATABASE_URL`: PostgreSQL connection string
- `REDIS_URL`: Redis connection string
- `KAFKA_BOOTSTRAP_SERVERS`: Kafka broker addresses

### Secrets Management
- API keys stored in Kubernetes secrets
- Database passwords managed by Vault
- TLS certificates auto-generated by cert-manager

## Monitoring

- Prometheus metrics: http://localhost:9090
- Grafana dashboards: http://localhost:3001
- Application logs: Elasticsearch/Kibana
- Distributed tracing: Jaeger

## Backup and Recovery

### Create Backup
```bash
./scripts/backup/create-backup.sh
```

### Restore from Backup
```bash
./scripts/backup/restore-backup.sh <backup-file>
```

## Troubleshooting

### Common Issues
1. **Pod not starting**: Check resource limits and node capacity
2. **Database connection failed**: Verify database credentials and network
3. **Service unavailable**: Check service discovery and load balancer

### Debug Commands
```bash
# Check pod logs
kubectl logs -f deployment/api-gateway -n trading-system

# Check pod status
kubectl describe pod <pod-name> -n trading-system

# Check service endpoints
kubectl get endpoints -n trading-system
```
